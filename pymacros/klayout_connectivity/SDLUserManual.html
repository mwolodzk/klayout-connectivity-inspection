SDL / CAS — instrukcja IHP SG13G2

SPICE/CDL → Netlist Import → zapis layoutu → Run SDL Analysis → Findings + flight-lines → CAS

1. Przygotowanie źródła

V1 przyjmuje netlistę SPICE/CDL. Jeśli projekt powstał w Xschem, najpierw wygeneruj z niego netlistę SPICE, a następnie wskaż ten plik w importerze.

2. Import expected connectivity

  1. Uruchom iic-ihp klayout -e.
  2. Wybierz File → Import → Netlist.
  3. W polu Source File wskaż plik .spice, .spi, .cir lub .cdl.
  4. W Tech Cell Mapping sprawdź mapowanie modeli na komórki SG13G2. Dla każdego modelu zweryfikuj Netlist Node Order.
  5. W zakładce Layout wybierz placement, na przykład Packed Mode with Padding, i kliknij Import.
  6. Przeczytaj raport. Ostrzeżenie wymienia instancje, których nie utworzono, wraz z powodem.
  7. Zapisz layout. Importer utworzy <layout>.sdl.json z expected connectivity i bindings.
Nie ignoruj brakującego modelu, złej liczby terminali ani symbolicznego parametru PCell. Popraw netlistę lub mapowanie przed analizą.

3. Analiza read-only

  1. Layout musi być zapisany i nie może mieć niezapisanych zmian.
  2. W panelu Connectivity Inspection kliknij Run SDL Analysis.
  3. Adapter SG13G2 uruchomi się w osobnym procesie batch, odczyta OAS/GDS i zapisze pliki diagnostyczne obok layoutu.
  4. Analyzer nie wywołuje zapisu geometrii. Nie zmienia komórek, instancji ani warstw layoutu.
Bezpieczeństwo: analiza jest read-only dla layoutu. Powstają wyłącznie sidecar <layout>.sdl.json, baza <layout>.sdl.lyrdb i log <layout>.sdl.log.

4. Connectivity Browser i CAS

  1. Kliknij Open Connectivity Browser.
  2. By Net pokazuje expected net i terminale; By Instance pokazuje instancje i ich piny.
  3. Findings pokazuje OPEN, SHORT, WRONG_NET i błędy powiązań. Kolumny można rozszerzać.
  4. Zaznaczenie instancji centruje i zbliża layout. Zaznaczenie finding wygasza pozostałe markery i podświetla cel.
  5. Statusy finding to active, visited i waived.

5. Flight-lines

Ustaw Flight-lines → All Opens. Linie powstają wyłącznie pomiędzy rozłącznymi komponentami tej samej oczekiwanej sieci. Dla k komponentów widoczne jest k-1 linii MST. SHORT nie jest pokazywany jako flight-line — trafia do Findings. Po domknięciu połączenia zapisz layout i ponownie uruchom analizę; odpowiednia linia zniknie.

6. Stale i typowe problemy

  • stale: zmienił się layout lub netlista; zapisz layout i uruchom analizę ponownie.
  • Pusty Browser: sprawdź, czy import utworzył sidecar i czy layout zawiera instancje z INSTANCE_INFO__*.
  • Brak Findings: upewnij się, że analiza zakończyła się poprawnie, a nie tylko oficjalna ekstrakcja NET_ONLY.

7. Test bez GUI

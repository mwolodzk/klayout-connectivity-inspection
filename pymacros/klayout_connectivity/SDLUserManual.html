SDL / CAS — podręcznik użytkownika

Netlist Import + Connectivity Inspection, wersja SDL v1

.sch lub SPICE/CDL → Attach SDL Source → read-only LVS/adapter → Findings + flight-lines → CAS

1. Szybki start

  1. Uruchom właściwy profil KLayout i otwórz zapisany layout. Dla XH018 użyj xh018-gds1131 layout/NAZWA.oas.
  2. Dla istniejącego albo zamrożonego layoutu XH018 nie wybieraj File → Import → Netlist. Wybierz Tools → Connectivity Inspection → Attach SDL Source... i wskaż źródłowy plik Xschem .sch albo gotową netlistę SPICE/CDL. SG13G2 korzysta obecnie z sidecara utworzonego przez Netlist Import.
  3. Plik .sch jest netlistowany automatycznie przez Xschem do pliku roboczego. Skrypt odczytuje istniejące instancje i tworzy tylko <layout>.sdl.json; nie regeneruje placementu.
  4. Wybierz Tools → Connectivity Inspection → Run SDL Analysis albo kliknij ten sam przycisk w panelu lub Connectivity Browser. Osobny proces KLayout batch otwiera OAS wyłącznie do odczytu, wykonuje extraction/comparison i aktualizuje <layout>.sdl.json oraz <layout>.sdl.lyrdb.
  5. Po zakończeniu Browser odświeży się automatycznie. Ustaw Flight-lines: All Opens; ręczny Refresh jest potrzebny tylko po zmianie plików poza GUI.
  6. Kliknij Open Connectivity Browser. To jest okno CAS tego przepływu; wyniki znajdują się w zakładce Findings.
Gwarancja bezpieczeństwa: Attach SDL Source i Run SDL Analysis nie wywołują importera placementu ani Layout.write. OAS/GDS jest wejściem read-only; zapisywane są tylko pliki diagnostyczne obok layoutu i logi *.sdl*.log.

2. Jak wypełnić Netlist Import

Ta sekcja dotyczy wyłącznie tworzenia nowego layoutu. Dla istniejącego layoutu XH018 przejdź do sekcji 3 i użyj Attach SDL Source, aby nie tworzyć nowych instancji.

Netlist Source

PoleWartość
Source FilePełna ścieżka do pliku .cdl, .cir, .spi albo .spice.
FormatSPICE Netlist (Simulation format).
HierarchyPreserve Hierarchy, aby zachować subcircuity i pełne ścieżki instancji.
Import Mode — komórkaZwykle New Cell; gotową komórkę można wskazać jako External Static Cell.
Import Mode — instancjaTech Cell Mapping dla elementu PDK, Netlist Cell dla innego subcircuitu albo External Static Cell.

Tech Cell Mapping

Zacznij od Restore Tech Defaults. Dla każdego modelu sprawdź Target Cell Type, Target Library, Target Cell, Parameters, Multiplier i Netlist Node Order. Kolejność węzłów musi odpowiadać terminalom modelu; inaczej wynik może zawierać fałszywe opens albo shorts.

Layout

  • Place first instance at X/Y — początek placementu w µm.
  • Maximum Number of Columns — liczba kolumn.
  • Fixed Grid Mode with Pitch — powtarzalny raster.
  • Packed Mode with Padding — placement bez nakładania bboxów, z odstępem.

Save Runset, Load Runset i Recent zapisują albo odtwarzają cały formularz. Po Import przeczytaj raport: nieznany model, niewłaściwa liczba terminali lub zła biblioteka wymagają poprawienia mapy.

3. Analiza expected kontra observed

Importer dostarcza expected connectivity i binding instancji, a LVS/adapter PDK dostarcza observed connectivity. Analiza jest wykonywana w osobnym procesie KLayout batch, więc edytor pozostaje responsywny. Wynik trafia do sidecara i Report Database, bez modyfikowania geometrii layoutu.

Istniejący layout i schemat Xschem

  1. Otwórz zapisany OAS właściwym skryptem PDK; dla projektu pilotażowego XH018: cd ~/eda/designs/projects/ECAUSIS/ic/dev/lvsh_diff2HV && xh018-gds1131 layout/lvsh_diff2HV.oas.
  2. Sprawdź, że layout nie ma znacznika [+]. Attach/Run celowo odmawia pracy na niezapisanym widoku, aby porównanie nie mieszało dwóch wersji geometrii.
  3. Kliknij Attach SDL Source... i wskaż lvsh_diff2HV.sch. Możesz też wskazać istniejący .spice, .spi, .cir lub .cdl. Dla .sch profil uruchomi Xschem bez GUI i użyje wygenerowanej netlisty tylko jako expected connectivity.
  4. Po komunikacie o dołączonym źródle kliknij Run SDL Analysis. Operacja jest read-only względem layoutu: nie regeneruje, nie przesuwa i nie nadpisuje instancji.

Dla pilota lvsh_diff2HV terminal map wiąże 13 urządzeń fizycznych. Pozostałych 6 urządzeń bez wiarygodnego access-point adapter nie zamienia na fałszywe MISSING; Browser pokazuje je jawnie w żółtym pasku jako SDL source warning.

Ważne dla SG13G2: polecenie LVS uruchomione bez source netlisty przechodzi w NET_ONLY i zapisuje jedynie *_extracted.cir. Nie uzupełnia pola snapshot w sidecarze SDL, więc Findings pozostaje puste. Użyj kompletnego polecenia poniżej.

Zapisz layout (brak znacznika [+] w tytule) i kliknij Run SDL Analysis w Browserze. Przycisk pokazuje stan pracy i po sukcesie automatycznie wczytuje Findings. Odpowiednik terminalowy dla automatyzacji SG13G2 (podmień layout i top):

PATH="$HOME/.local/bin:$PATH" iic-ihp klayout -b \
  -r /foss/designs/.klayout-ihp/salt/NetlistImportPlugin/pymacros/klayout_netlist_importer/sg13g2_sdl_batch.py \
  -rd layout=/foss/designs/quenching/layout/NAZWA.oas \
  -rd top=NAZWA

Po sukcesie ostatnia linia terminala zaczyna się od SG13G2_SDL_BATCH_OK. Powstaną pliki NAZWA.oas.observed.json, NAZWA.oas.sdl.json z niepustym snapshot oraz NAZWA.oas.sdl.lyrdb.

Dla XH018 GUI automatycznie wybiera xh018_sdl_batch.py na podstawie technologii TECH_XH018_1131 albo profilu .klayout-xh018*. Nie trzeba wybierać adaptera ręcznie.

Przed oglądaniem linii sprawdź, że snapshot ma stale=false. Po zmianie layoutu albo netlisty wynik staje się nieaktualny i analizę trzeba powtórzyć.

4. Flight-lines oraz Findings/CAS

  1. Otwórz Tools → Connectivity Inspection → Show Connectivity Panel.
  2. Włącz Show Connectivity Information i Flywires.
  3. Wybierz tryb Flight-lines: Off, Selected Nets, Selected Pins, Selected Instances albo All Opens.
  4. Kliknij Open Connectivity Browser. Gdy sidecara brakuje, użyj Attach SDL Source...; gdy snapshot jest pusty albo nieaktualny, zapisz layout i kliknij Run SDL Analysis.
  5. W zakładce Findings filtruj typy i zaznaczaj jeden lub wiele wpisów. Powiązane markery pozostają jasne, a pozostałe są wygaszane o 65%, bez ukrywania kontekstu layoutu. Odznaczenie wszystkich wpisów przywraca pełną jasność.
  6. Szerokość każdej kolumny można zmieniać, przeciągając separator w nagłówku. Zamknięcie Connectivity Browser automatycznie usuwa wybór i przywraca pełną jasność overlay.
  7. W zakładce By Instance kliknij instancję, aby wycentrować i przybliżyć jej bbox. W By Net najpierw wybierz sieć, a następnie instancję w prawej tabeli — widok zostanie wycentrowany w ten sam sposób.
  8. Dostępne statusy findings to active, visited i waived.

Flight-lines są rysowane wyłącznie dla rzeczywistych OPEN. Sieć złożona z k rozłącznych komponentów otrzymuje k-1 linii MST pomiędzy najbliższymi access points. SHORT, WRONG_NET, UNBOUND, MISSING, MASTER_MISMATCH i PARAMETER_MISMATCH są raportowane w Findings, lecz nie generują linii trasowania.

5. Profile PDK

  • SG13G2 / iic-ihp: pełny przepływ jest dostępny w profilu produkcyjnym.
  • XH018 / iic-xh018: wspólny GUI rozpoznaje TECH_XH018_1131, korzysta z mapy XH018 i read-only adaptera BasicLVS/NetTracer. Istniejący layout można połączyć ze źródłem bez importowania placementu.

6. Diagnostyka

  • Brak wszystkich linii: sprawdź sidecar, stale, opcję Flywires i tryb widoczności.
  • Pusty Findings i komunikat snapshot is empty: wykonano tylko attach/import albo LVS NET_ONLY; uruchom Run SDL Analysis z sekcji 3.
  • Puste By Net i pusta lista pinów: importer zna mapę logiczną, ale PCell nie udostępnił fizycznych PIN_INFO. Po analizie SDL używane są access points z adaptera; wcześniej nie należy zgadywać położenia terminali.
  • Brak linii przy SHORT: to prawidłowe — SHORT jest tylko findingiem.
  • Po domknięciu rozwarcia zapisz layout, ponów analizę i kliknij Refresh; odpowiednia linia ma zniknąć.
  • Po przesunięciu instancji layout ma stan niezapisany. Ostatni zapisany overlay pozostaje widoczny, ale jest przygaszony i oznaczony jako stale. Zapisz OAS, a następnie użyj Run SDL Analysis obok Refresh w panelu albo analogicznego przycisku w Browserze. Adapter odzyskuje stabilną nazwę przesuniętej instancji ze zgodnego bindingu modelu.
  • Brak pinów static cell: sprawdź zachowane etykiety terminali i binding instancji.
  • Żółty SDL analysis warning oznacza terminal, dla którego adapter nie znalazł jednoznacznego fizycznego access point. Taki terminal pozostaje widoczny logicznie w By Net/By Instance, ale nie jest używany do fałszywego SHORT ani do markera fizycznego.

Menu produkcyjnego IHP:

PATH="$HOME/.local/bin:$PATH" iic-ihp klayout

Kontrolowany IHP: jeden OPEN, jedna flight-line i otwarty manual (proces kończy się po maksymalnie 45 s):

PATH="$HOME/.local/bin:$PATH" \
IHP_KLAYOUT_HOME=/foss/designs/.klayout-ihp-sdl-dev \
iic-ihp klayout -e \
-r /foss/designs/.klayout-ihp-sdl-dev/salt/ConnectivityInspectionPlugin/tests/klayout_sdl_gui_smoke.py \
-rd expected_findings=1 -rd expected_lines=1 -rd expected_instances=2 \
-rd show_manual=true -rd hold_seconds=45 \
/foss/designs/.klayout-ihp-sdl-dev/sdl-tests/results/ihp_sdl_smoke.oas

Rzeczywisty projekt XH018 (skrypt ustawia właściwy PDK i profil):

xh018-gds1131 layout/lvsh_diff2HV.oas
